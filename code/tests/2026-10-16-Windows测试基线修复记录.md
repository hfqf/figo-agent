## 第二轮：运行时兼容修复

用户明确授权修复 Storage 初始化失败连接泄漏、Git 参数引号、终端 `/bin/sh` 以及命令取消稳定性。对应源码由本任务独立修改，主线程不同时编辑这些文件。

### TDD 红证据

先修改测试，再运行以下命令；此时尚未修改运行时源码：

```powershell
npm test -- tests/storage/storage-manager.test.ts tests/tools/git-tools.test.ts tests/tools/command-tools.test.ts tests/ui/terminal-service.test.ts --reporter=json --outputFile=../.figo-agent/windows-runtime-tdd-red.json
```

退出码 1：4 个文件全部存在失败，22 项中 11 项失败、11 项通过。

- Storage：在原有迁移异常、事务回滚断言之后，验证数据库文件可以重命名，实际因内部连接泄漏报 `EBUSY`。
- Git：保留原始功能用例，增加退出码为零的断言；另外验证包含空格、单引号、双引号、`&`、百分号、美元符号和反引号的文件名及提交消息原样传递。三项失败。
- 命令取消：连续三次等待真实子进程写出启动标记后取消，三次均约 5 秒才返回，超过 2 秒限制；超时用例也读到了不应出现的延迟输出。
- 终端：真实运行本机命令、启动后主动停止以及超时三个用例均失败，原因是 Windows 无法启动固定的 `/bin/sh`。

### 最小实现

| 文件（相对 `code/`） | 修改及保留的语义 |
| --- | --- |
| `src/storage/storage-manager.ts` | 数据库创建后的初始化过程置于 `try/catch`；失败关闭连接并重新抛出原异常。迁移顺序及其回滚逻辑不变，成功时连接仍归调用方持有。 |
| `src/tools/git-tools.ts` | 使用 Git 可执行文件与参数数组，避免用户参数再次被 shell 展开。保留 cwd 工作区校验、Policy、Trace、超时、输出截断和原有 ToolResult 状态含义。 |
| `src/tools/command-tools.ts` | 为 shell 命令与直接程序调用共用原有输出收集过程；Git 使用 `runFileCommand`，`run_command` 仍使用 shell。主动取消与超时均停止进程树，重复停止不重复派发。 |
| `src/utils/child-process.ts` | 统一进程树停止：Windows 用绝对系统路径启动 `taskkill.exe /PID <pid> /T /F`，不经 shell，窗口隐藏；POSIX 保留 detached 进程组的 `SIGTERM`，组不存在时回退直接子进程。 |
| `src/ui/terminal-service.ts` | Windows 使用 Node 的本机 shell 选择规则；POSIX 继续用 `SHELL` 或 `/bin/sh` 的 `-lc` 登录 shell。停止及超时共用进程树停止逻辑，保留审计摘要、状态和目录切换行为。 |

增强的测试文件为 `tests/storage/storage-manager.test.ts`、`tests/tools/git-tools.test.ts`、`tests/tools/command-tools.test.ts`、`tests/ui/terminal-service.test.ts`。取消测试还通过已记录的 PID 验证子进程不存在；终端重复停止只记录一次事件，随后可以继续执行新命令。

- 一次相关复验为 34 项通过、1 项失败（`windows-runtime-final-related.json`）。失败断言为启动确认用例的总耗时 2.274 秒，取消计时和 PID 退出均通过。恢复并保留原有固定 50ms 取消、总耗时小于 2 秒的独立用例；新增三个启动确认用例从真正发出取消时计时，仍必须小于 2 秒并检查子进程不存在。启动和取消的时间口径分开验证，未提高取消耗时上限。
