**目标：** 修复原生工具响应误判，移除不合理测试窗口，再使用三个本地模型完成同历史、三次配对复测。

**架构：** 原生结构化动作与文本 JSON 分开解释，仍汇合到现有 Tool Runtime 与 Policy；验收脚本复制同一模型的原始历史，分别执行关闭、正常测试窗口开启分支。Pi 核心算法、生产窗口、R=16384、K=20000不调整。SQLite 与抓包保存成功、失败、来源和测量数据。

**技术栈：** TypeScript、现有 Node.js AgentLoop、Vitest、SQLite、现有 OpenAI-compatible Provider。

## 一、证据与约束

- `agent-loop.ts` 当前的 `mixed_native_tool_response` 将合法原生调用与正文共存判为错误；对应旧 GPT 抓包首请求158.380秒，格式修复请求再运行21.586秒后触及180秒整轮上限。
- OpenAI Chat Completions 消息结构允许 `content` 与 `tool_calls` 共存：[官方契约](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。文本协议仍只允许一个完整工具块或最终答案。
- 旧压力测试 W=35440、R=16384，触发阈值19056低于K=20000；DeepSeek一次后续Turn产生3次摘要。保留旧结果，不冒充日常性能基准。
- 参数仍统一进入 `code/figo-agent.config.json`。新增 `acceptance.piCompaction` 仅由验收脚本读取，不加入 AgentLoop 运行控制；正常测试窗口49152、配对次数3、整轮超时180000毫秒。压力场景单独命名，不纳入默认配对列表。
- GPT中转真实窗口未知，正常测试窗口不得写回模型元数据。凭据只从用户指定历史提取到0600隔离配置，实验结束清理，不进入报告、SQLite或Git。
