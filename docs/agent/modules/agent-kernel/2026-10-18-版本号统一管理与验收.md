# 版本号统一管理与验收

## 已确认设计

当前产品版本为 `0.0.1-beta`，唯一事实源是 `code/package.json` 的 `version`。锁文件同步该值，不再单独维护版本常量。CLI、工作台、Electron 关于面板和安装包验收路径均读取此来源。

产品版本不等于配置结构的 `version`、SQLite 的 `user_version`、提示词指纹或文件内容版本；本轮不修改这些数据版本，不实现自动更新，不自动创建 Git tag 或提交。

## 实施计划

### 1. 元数据与 CLI

- [x] 先增加版本元数据、锁文件一致性和 CLI 隔离进程测试，确认旧实现不满足验收。
- [x] 将 `code/package.json` 与 `code/package-lock.json` 的根项目版本改为 `0.0.1-beta`。
- [x] 新增 `code/src/version.ts`，导出 `appVersion: string`；从当前程序目录的 `../package.json` 读取，不能读取用户工作区的 package.json。
- [x] CLI 的 `--version` / `-v` 在加载内核前输出版本并退出，不创建 Session、SQLite 或模型请求。启动文案使用同一版本，新文案放中文资源。
- [x] 与程序一同发布的内置插件使用产品版本，测试样例的独立插件版本不改。

### 2. 工作台与 macOS

- [x] ZIP 验证检查包内版本、原生 `Info.plist` 版本与源版本一致；窗口 E2E 检查实际 App 和页面版本。

### 3. 发布与验收

- [x] 更新 README 的版本规则和查询命令；记录本次版本，不宣称现有全部功能获得公开发布放行。

- [x] 记录结果和新包路径，未通过项目不得标记通过。

## 验收命令

```bash
npm --prefix code test -- tests/version.test.ts tests/cli/version.test.ts tests/ui/local-api.test.ts
npm --prefix code test
npm --prefix code run typecheck
npm --prefix code run web:typecheck
npm --prefix code run dev -- --version
npm --prefix code run desktop:make
npm --prefix code run desktop:verify:package
npm --prefix code run desktop:test:e2e:package
npm --prefix code run desktop:test:dsml:package
```

## 禁止放行条件

1. CLI 查询版本会创建业务数据或调用模型。
2. 工作台、App、包内元数据与 ZIP 文件名的版本不一致。
3. 升版后验收脚本仍尝试检查旧版本 ZIP。
4. 将产品版本误写成 SQLite 迁移版本，或改写既有用户记录。
5. 本地模型密钥进入源码、文档、安装包或测试产物。
