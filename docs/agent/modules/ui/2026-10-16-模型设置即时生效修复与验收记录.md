# 模型设置即时生效修复与验收记录

## 1. 用户反馈与根因

2026-10-16，用户反馈编辑 API Key 后保存失败，并明确指出“保存成功后还要重启服务”不符合预期。

排查服务错误日志只有 SQLite 实验性警告，不能据此宣称保存成功或认定具体失败请求。通过源码与隔离配置复现两个问题：

1. 仓库配置中的多个模型启用但密钥留空。保存一个模型时，其他未改动条目的空密钥阻断整个保存；缺少密钥的校验异常还被映射为 500，只显示“服务处理失败”。
2. 设置接口只写 JSON 文件，Provider、默认模型、容量查询、页面模型列表和密钥脱敏集合仍沿用启动快照，所以旧界面要求重启。

端口边界：`4317` 为正式工作台；`4318` 为隔离 Trace 演示，未开启配置写入，不用于配置真实密钥。

## 2. 功能与交互约定

1. 保存成功表示配置已原子落盘，且当前进程的后续请求已使用新配置；提示改为“模型配置已保存并立即生效”。用户不需要为后续模型设置保存重启服务。
2. 当前 Session、Task、SQLite、Trace 和输入草稿不因配置保存而重建。新增、删除、禁用模型，以及修改密钥、地址和模型 ID，必须同步更新可用模型与默认选择。
3. 普通请求和压缩请求统一使用新的 Provider；不改变 Pi 压缩算法。模型容量字段与运行时查询保持一致，不新增普通调用的输出上限策略。
4. 沿用原有安全边界：有活动 Run 时返回 409，待运行完成后保存。设置保存、默认模型切换和工作区切换互斥，读取请求正文前即占用对应写锁。
5. 未改动的空密钥模板可以保留，不强迫一次配置全部模型，也不静默启用、禁用或切换其他模型。新增启用、切换连接、清除已有可用密钥、把未配置条目改为当前模型时仍校验密钥。当前模型未配置时页面如实提示。
6. 本页与其他已连接页面通过保存回调和 SSE 更新。模型列表丢弃旧请求结果；bootstrap 使用递增请求序号拒绝旧响应覆盖最新状态。

## 3. 数据流与职责

```text
浏览器草稿 + 配置版本
    -> 同源鉴权 / CSRF / 写互斥 / 活动 Run 校验
    -> ModelSettings 校验与乐观版本检查
    -> Kernel 经 PluginHost 获取模型连接注册表，准备新的 Provider 快照
    -> 临时文件写入与原子 rename
    -> 同步提交 Provider / 默认模型 / 容量元数据 / 脱敏集合
    -> settings.models.updated（仅 ID 与版本，不含密钥）
    -> HTTP 成功响应 + SSE
    -> 默认选择、模型列表、未配置状态即时更新
```

`ConfiguredModelProviders` 是静态内置插件中的连接配置注册表，不是动态插件加载或插件热插拔。AgentLoop 仍通过 PluginHost 获取 Provider，不直接实例化具体模型实现。

运行时准备失败不得写新文件；写文件失败不得激活已经准备的新连接。文件写入成功后同步提交，不重新读取配置文件，避免落盘与激活之间读入另一份配置。配置版本冲突保留原数据，提示刷新设置重试。

脱敏集合使用共享数组，已有查询服务与 SSE 同步看到新增密钥；本进程内轮换、删除后仍保留旧值用于历史事实脱敏。替换时按密钥长度降序，防止前缀重叠造成后缀泄露。密钥不进入设置响应、变更事件或验收图片。

## 5. 部署边界

本轮修改服务端代码需由开发者加载新版本，这是一次代码升级部署，不是今后保存模型设置的操作步骤。用户已填写的本机密钥不得覆盖、清空或提交到版本库；提交前仍须按项目规则清理密钥并扫描。

2026-10-16 已完成正式 `4317` 服务的代码升级加载，升级前确认无活动 Run 或运行中终端命令；升级后引导与模型设置接口正常，运行时默认选择与已保存选择一致。Chrome 直连验证设置页面可见、密码输入框不回填已保存密钥、页面无异常。此部署按现有启动流程创建新的 Session，但历史数据保留；这与后续设置保存不重建 Session 的热更新行为分别记录。用户只需刷新一次页面加载新前端，今后保存模型配置无需重启服务。
