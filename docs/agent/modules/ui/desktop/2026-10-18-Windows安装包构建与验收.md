## 构建边界

继续使用 Forge 生成应用目录，复用既有敏感文件排除规则；仅在 Windows 安装器阶段使用固定版本 `electron-builder@26.15.3` 的标准 NSIS 模板，没有迁移 Mac 打包工具或另写安装器脚本。

构建顺序为：TypeScript 编译、Vite 打包、品牌 PNG 转多尺寸 ICO、Forge 生成 `win32/x64` 应用、扫描应用包、NSIS 生成安装器、解开最终安装器并校验载荷。

- `code/electron-builder.windows.cjs`：仅存 Windows 构建配置，不存模型或用户运行参数；应用 ID 保持 `cn.figo.agent`，不复制产品版本。
- `code/scripts/build-windows-icon.mjs`：通过 `png-to-ico@3.0.2` 将现有品牌 PNG 编码为 16、32、48、256 像素 ICO，不重新设计图案。
- `code/e2e/desktop-windows-verify.mjs`：检查主程序 PE 架构、版本、必需资源、两张引导图、敏感文件和密钥；再解开最终安装器，对比其中主程序与 `app.asar` 的 SHA-256，确认包含卸载程序。
- Mac 的 `desktop:make` 和现有 `forge.config.cjs` 保持不变；未自动上传、发布、签名、提交 Git 或更改用户数据。

## 重复构建

在仓库根目录执行：

```bash
npm --prefix code run desktop:make:win
npm --prefix code run desktop:verify:win
```

本机 GitHub 下载连接超时，本次使用国内镜像；下载的 Electron Windows 运行时已与已安装 Electron 包内的校验表核对，SHA-256 为 `eee30dc8fa1f5ea95490e59f44e46ea68dd24c6e93d22facf70fe5c2d4c2665c`。未跳过校验。

macOS / Linux 下指定镜像：

```bash
cd code
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ \
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ \
npm run desktop:make:win
```

Windows PowerShell 下指定镜像：

```powershell
$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR = "https://npmmirror.com/mirrors/electron-builder-binaries/"
npm --prefix code run desktop:make:win
```

镜像只是本次构建的环境选择，不写入 Agent 运行配置或更改系统代理。

## 经验

“生成安装器”“确认装进了正确文件”“在目标系统运行正常”是三道不同门槛。交叉构建能完成前两项，第三项必须补目标系统的直接证据；静态校验应解开最终安装器核对，而不是只检查旁边的应用目录。

工具依据：[Forge 应用打包](https://www.electronforge.io/core-concepts/build-lifecycle)、[electron-builder v26 NSIS](https://www.electron.build/v26/docs/nsis/)、[v26 Windows 配置](https://www.electron.build/v26/docs/win/)。工具选项以本机固定版本源码和本次实际输出为准，不混用未发布版本的配置键。
