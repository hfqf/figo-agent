## 二、专项场景

- [x] 同 Turn 多请求在压缩前后显示各自消息，最新摘要变化不污染历史。
- [x] 消息切点精确到 sourceRef，同一 Turn 的前缀和保留后缀分别展示。
- [x] 新 Markdown 条目、旧 JSON 检查点及同 Task 混合数据分别解释。
- [x] 多次滚动摘要可以沿 baseEntryId 追溯。
- [x] 一次压缩多个摘要请求全部可查，用量逐请求统计且未知不补零。
- [x] 跳过、未知窗口、失败、取消、提交冲突不显示成功压缩。
- [x] 条目已保存但 completed 事件缺失时如实显示。
- [x] 手动压缩无触发 Turn，Task 事件和抓包锚点不混淆。
- [x] 恢复前失败、消息省略、摘要和重试请求可定位，工具不会因查看而重放。
- [x] 当前 omitted 标记不改变早期请求的实际发送内容。
- [x] 原生 content 与 tool_calls 共存，过程说明不误标为最终答案。
- [x] 消息快照缺失时兼容降级，实际抓包仍可查看。
- [x] 前后指标缺失/增长如实展示，不宣称成本收益或摘要无损。
- [x] 分页同毫秒无重复漏行，达到限制明确未查完。
- [x] 切换 Task/工作区、标签、请求及 Live 更新不串数据、不抢历史选中。
- [x] 所有区域及导出脱敏，文件先看执行时快照再看当前版本。

## 五、审查与修复留痕

独立审查发现的四项阻断已分别复现并修复：正文截断的密钥前缀、异常引用跨 Task 构建快照、长摘要链 SQL 参数上限、恢复摘要入口缺重试抓包。额外复查还发现嵌套 checkpoint 归属缺口，已在共享查询加 Task 条件，专项服务保留错误归属提示；独立复核通过。

截断修复已先复现泄露前缀，再验证在 SQL 护栏片段完成凭据替换且长度不缩短，之后才截可见正文，防止尾片段被缩短替换拉入可见区。未闭合引号的凭据赋值也脱敏。内存 SQLite 与 API 相关 9 项通过；查询与既有查询回归合计 39 项通过。

长链回归使用 90 条摘要、每条 200 个来源；构造 SQL 前最多保留每组 1000 个关联并标记截断。恢复链只沿明确的 `recoveryOfRequestId` 获取失败与重试抓包。UI 的 Live 尾窗口在没有普通游标时隐藏“下一页”，避免出现无效控件；来源被限额裁掉时提示未查完，不断言原文不存在。

本轮仓库下未发现已有 `figo-agent.db`，因此浏览器使用运行时真实表结构的隔离 SQLite；没有抽查用户个人历史库，也没有以演示数据冒充真实模型调用。
