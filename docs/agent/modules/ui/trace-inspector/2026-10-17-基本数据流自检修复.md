## 目标与证据

## 架构与约束

继续使用现有只读 QueryService、LocalApi、DTO 和 React 页面，不新增状态源。查询保留 JSON 结构，仅把长字符串转换为带字段定位的脱敏预览；通过归属明确、字段白名单的只读接口继续读取脱敏内容。原始 wire 与结构化响应分开，不因 wire 过大丢弃正文和 usage。列表按明确 ID 获取工具与请求指标，区分实测、估算、不适用、进行中、未记录和模型未提供。默认只看业务事实，传输事件保留显式入口。新增运行限制进入统一 JSON，文案进入中文资源。

不改 AgentLoop、工具执行、Pi 算法或压缩阈值；不修改原始抓包，不发送付费模型请求；不输出本机密钥，不自动提交或推送。

### 验证中的失败与修复

1. 长请求结构丢失、字段读取接口缺失：新增字段测试先失败，保留结构和按需读取后通过。
2. 来源未返回时仍沿用“未查完或字段已截断”文案：改为明确来源尚未全部加载。
3. 浏览器旧断言依赖“未查完”旧文案：改为校验当前中文资源的分页语义。
4. macOS 临时目录经 realpath 后由 `/var` 变为 `/private/var`：测试比较规范路径，实际工作区切换成功，不改业务路径逻辑。
5. 长工具错误被 React 当普通对象渲染：失败表格和详情复用字段预览，真实浏览器验证加载与重试。
6. 独立审查补充原始 JSON 伪造字段引用、超长来源标识、不可读取的深字段引用、合法 JSON 深度溢出、完整响应预算遗漏封装等边界，各自补回归，不忽略来源、不把护栏报成无效 JSON。
7. 最后一次集成回归曾在原“超大输入即截断”断言失败：现在只读持久化 ContextPack，不回填原始 Turn 输入。改用断言验证包和条目完整、原始大输入未混入；实际未丢快照就不标截断。损坏 JSON 降级断言保留，最终全量重跑通过。

安全协议护栏另限定 JSON 嵌套深度最多 128 层、字段路径最多 32 段；深正文在合法父路径折叠，超出安全读取范围时明确说明，不能静默丢失或声称无效 JSON。完整响应预算连同 JSON 封装及范围说明计入；独立边界复现中预算 1594 字符，最终响应 1591 字符并标记截断。

## 同日补充：模型标签默认请求选择

用户实际使用指出：选中不含 requestId 的普通事件后，当前详情已有抓包，两个模型标签却停在“请选择请求”。根因是前端只使用手选值或事件直接引用，没有为范围内已存在的请求建立默认选择。上一轮浏览器验收先手动选中抓包，漏验了这个入口，不将先前通过结论作为该问题已覆盖的证据。

修复限定在 UI：进入模型标签后按“已有手选 → 明确引用 → 当前详情第一条抓包”选择，随后复用正常请求查询，刷新对应的正文、上下文投影和下拉框。普通事件默认请求的列表顺序来自服务端受限查询，不按时间接近推断因果，不跨详情范围寻找请求；真实引用的抓包缺失时继续显示缺失，不用其他抓包掩盖。没有抓包时不编造默认。

新增两项状态测试和两项真实浏览器回归先失败、修复后通过，覆盖两个模型标签自动选择、手动改选、标签保留、事件重选、Task 隔离和只读 GET。真实 `task_38b293e7-210e-49ed-a40f-7cb01e1aca24` 中选中无 requestId 的 `trace:trc_8a30a14b-e5d7-42ef-8588-3593562d3082`，不操作请求下拉框，页面自动选择 `llm_req_15f0132b-812e-48fb-b4ca-e7638d562839`，展示 2 条请求消息和 152 字符响应，浏览器运行错误 0。
