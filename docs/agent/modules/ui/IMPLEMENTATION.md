# 本地 Web UI 实施路线

> 状态：阶段 A-C 的本地 Web 首期实现与自测已完成（2026-10-12）；阶段 D 未实施。实测范围与剩余边界见[验收记录](./ACCEPTANCE.md)。

## 文档索引信息

- 背景：本地 Web 路线与三栏效果图已确认，CLI 与 Web 现共用 AgentKernel。
- 目标：把 UI 设计转成按依赖顺序执行、逐阶段验收的工程任务。
- 标签：React、Node.js、本地 Web、SSE、运行协调、文件安全、验收门槛。
- 适用范围：后续 UI 开发排期、任务拆分、代码评审和放行。
- 后续可用方向：细化逐任务测试用例、命令和回滚方案。

## 前置条件

1. 保留 CLI 作为基准入口，先记录现有全量测试、类型检查和构建结果。
2. 不改动用户本机的真实 API Key；Web 服务和前端包不得读取或复制密钥。
3. `design.md`、[工作台设计](./workspace.md)、[检查器设计](./inspector.md)、[运行协议](./runtime-protocol.md)同时作为行为约束。
4. 每阶段先补失败测试，后实现，再按[验收文档](./ACCEPTANCE.md)复核；失败不得进入下一阶段。

## 阶段 A：应用层与安全底座

- [x] 抽出 CLI/Web 共用的 Run 协调边界，保证一条用户输入只创建一个 Turn；新增 Run 状态、幂等键与工作区单写者约束。
- [x] 增加有序、脱敏的 UI 事件 outbox；状态与事件原子落库，支持按 `seq` 重放。
- [x] 建立同源本地 HTTP 适配器与认证、Origin/Host、CSRF、请求大小限制；只监听本机地址。
- [x] 现有 CLI 测试全部保持通过；API 测试证明不认证不能查询状态/SSE 或提交 Turn。

**放行点：** 异步 Turn、进度事件、断线续接和本地安全用例通过，才开放可执行页面。

## 阶段 B：核心工作台

- [x] 建立 React + TypeScript + Vite 前端，按三栏视觉基线实现顶栏、Task 列表、对话区、右侧检查器容器与响应式抽屉。
- [x] 实现 Task 读/写命令和 Turn 提交；运行卡片只显示已产生的真实事件，不模拟模型逐字流。
- [x] 实现只读文件树、文本预览、行号、搜索、行区间选择；服务端拒绝敏感路径、越界符号链接、二进制和超大文件。
- [x] 实现“引用选中行”结构化输入，服务端重读文件并校验版本，再交给 ContextBuilder；预览本身不进入上下文。

**放行点：** Task/文件/对话三条主路径可用，刷新不中断服务中的 Run，引用来源在 ContextPack 与抓包中可核对。

## 阶段 C：证据检查器

- [x] 上下文标签展示候选、纳入/排除、取舍原因、估算与压缩边界。
- [x] 抓包标签展示同一 Turn 的全部请求、脱敏请求/响应、用途和请求级 TokenUsage；缺失值保持未知。
- [x] Trace 标签展示稳定顺序、事件详情与真实关联 ID；无直接关联时明确提示。
- [x] 做好空态、失败态、长 ID、跨 Task 切换和老数据回填后的查询测试。

**放行点：** 同一 Turn 的“准备了什么、实际传了什么、程序做了什么”三处事实能互相核对，且不泄漏密钥。

## 阶段 D：增强与桌面端

- [ ] 分别设计并验收 Agent 内核可取消执行、交互式审批恢复、模型逐字流和按 Turn 固定的 Diff；没有对应协议时不显示可操作控件。
- [ ] 本地 Web 完整通过后，再选择桌面容器封装同一 Web 前端与 API/SSE；桌面桥只提供最小受控原生能力。
- [ ] 桌面版复用阶段 A–C 的行为与安全测试，不复制一套 Context/Tool/Policy 逻辑。

## 退出标准

测试命令、真实接入 ID、截图位置和剩余专项场景记录在[验收记录](./ACCEPTANCE.md)。任何禁止放行条件发生时记录原因并回到对应阶段，不以效果图、演示数据或“页面看起来正常”代替验收。
